# Church Cap v0.9.0 release notes

Church Cap v0.9.0 adds dedicated, single-language presentation outputs for ProPresenter, OBS, and Room Display while keeping captions and translation on the local Church Cap computer.

| Platform | Release asset | Public-release requirement |
| --- | --- | --- |
| Apple Silicon Mac | `Church-Cap-v0.9.0-macOS-Apple-Silicon.dmg` | Developer ID signed, Apple notarized, and stapled |
| Windows 10/11 x64 | `Church-Cap-v0.9.0-Windows-x64-Setup.exe` | NSIS installer; Authenticode status stated on the release page |
| 64-bit Linux | `Church-Cap-Linux-CLI.tar.gz` | Curated CLI archive with matching `.sha256` |

## Highlights

- ProPresenter setup now has a concise five-step in-app guide, its own full guide at `/propresenter/help` (separate from the OBS guide at `/obs/help`), a searchable installed-language selector, a copyable `/propresenter?lang=…` Web-object URL (older `/obs?integration=propresenter` Props keep working), connection status, and an OBS fallback.
- **Operator → Updates → Check for updates** opens the installed Mac or Windows app on Settings and runs its signed-updater check. On Linux it runs `update-linux.sh --check`.
- The OBS setup guide is five steps in both the quick and full guides.
- OBS and Room Display can each use one fixed English or translated output without counting the presentation computer as a congregation viewer.
- The first-run assistant guides password, security, audio input, performance, caption languages, and optional spoken translated audio. A translated language pack is saved with Automatic availability, so visitors can choose any installed language; Restricted mode starts empty and only ever contains languages the operator selects.
- Native Mac and Windows settings now include a guarded factory reset. It stops Church Cap safely, requires `RESET`, removes only known Church Cap local state and downloaded models, restarts, and opens complete onboarding.
- Linux includes `./factory-reset-linux.sh` with the same explicit confirmation and onboarding result.
- Installer artwork remains consistent across platforms and no longer contains a version number, so the approved artwork can be reused.
- The desktop dependency lock removes four disclosed Rust vulnerabilities in its XML, TLS, and time-handling dependency paths; the release audit now runs in CI.

## Updating from v0.8.0

Mac and Windows keep the existing native application data during a normal update. Linux replaces only packaged application files while preserving `.env`, the Python environment, models, configuration overrides, logs, certificates, and rollback data. Factory reset is never part of an update and runs only after an explicit confirmed request.

The encrypted private key trusted by the public v0.8.0 Mac and Windows applications could not be recovered. For safety, v0.9.0 rotates to updater public-key ID `25BF3CCF4B6CBB01`. Existing v0.8.0 desktop users must therefore download and run the v0.9.0 DMG or Windows installer once; the installer preserves their Church Cap settings and local data. Do not use **Check for updates** in v0.8.0 for this upgrade: v0.8.0 will stop at signature verification without changing the installation. Automatic signed desktop updates resume from v0.9.0 onward after the corresponding platform manifest is published. Linux is unaffected by this key rotation and continues to select the latest public non-prerelease GitHub release and verify the curated CLI archive against its SHA-256 file.

## Before a service

Rehearse the real audio interface, selected caption model, every required translated output, and the actual ProPresenter/OBS display path for 60–90 minutes. ProPresenter Props must be both included in the active Look and shown. If its Web object is unreliable on the presentation computer, use the documented OBS composite fallback.

## Platform notes

- macOS: Apple Silicon, Developer ID signed and notarized public DMG required.
- Windows: 64-bit NSIS installer. Check the release page for its Authenticode status and verify the published SHA-256.
- Linux: 64-bit terminal-first package for supported Debian/Ubuntu and RHEL/AlmaLinux families; other documented package-manager paths remain available but require representative testing.

## Known limitations

- The Windows installer is not Authenticode-signed, so Windows may show SmartScreen. Verify the published SHA-256 before continuing.
- The Windows installer bundles CPU-only PyTorch. NVIDIA acceleration applies to Faster Whisper/CTranslate2 and the Broad CTranslate2 language pack, not the PyTorch compatibility pack.
- After v0.9.0 manifests are published, v0.8.0 desktop applications that check for updates will see v0.9.0 offered but cannot verify it; the install stops without changing the existing installation. Install v0.9.0 manually instead.
- Linux remains terminal-first. Linux NVIDIA/CUDA acceleration has not been validated for this release.
- AI-generated captions and translations can be inaccurate. Rehearse with the exact computer, audio route, models, and languages before a live service.

## Release evidence

Final artifact sizes, SHA-256 values, Apple notarization, and updater-signature evidence are published with the GitHub Release and its `SHA256SUMS` files rather than in this source file, because release artifacts are built after this source is frozen. Earlier v0.9.0 candidate DMGs and hashes recorded during development are superseded and must not be published.
