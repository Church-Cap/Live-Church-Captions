# Church Cap v0.9.0 dependency audit

Audit date: 15 October 2026

This audit covers the dependencies locked for the v0.9.0 release candidate. It supplements the historical [v0.8.0 audit](V0.8.0_DEPENDENCY_AUDIT.md); the v0.9.0 decisions below are the current release record.

## Tools and results

| Area | Tool | Result |
|---|---|---|
| Python source | Bandit 1.9.4, high severity | No finding |
| Python runtime dependencies | pip-audit 2.10.1 against `requirements-packaged.txt` | Ten records representing six distinct advisory IDs in two packages; all six are explicitly reachability-controlled below |
| Desktop production JavaScript | npm audit | No vulnerability |
| Rust desktop lockfile | cargo-audit 0.22.2 / RustSec database of 20 October 2026, after the Tauri 2.12.4 refresh, removal of the updater `zip` feature, and the `rustls-webpki`/`webpki-root-certs` update | No vulnerability; five allowed transitive warnings (`proc-macro-error`, `glib`, `zbus_names`, `zvariant`, `zvariant_derive`) |

The Tauri refresh removed the five `unic-*` informational warnings. The remaining `proc-macro-error` (RUSTSEC-2024-0370, unmaintained) and `glib` (RUSTSEC-2024-0429, unsound) warnings are Linux GTK/Tauri transitive dependencies. The October 2026 database added three unmaintained warnings for `zbus_names` (RUSTSEC-2026-0371), `zvariant` (RUSTSEC-2026-0370) and `zvariant_derive` (RUSTSEC-2026-0372); they come from `zbus`, which `tauri-plugin-opener` and `tauri-plugin-single-instance` use only on Linux. `cargo tree` places none of the five warned crates in the Windows or macOS build, and Church Cap's distributed Linux CLI does not include the desktop wrapper. These warnings are not reported vulnerabilities, but should be rechecked when Tauri refreshes those dependency families. The audit printed a crates.io index update warning (`registry: No such file or directory`) while scanning the current RustSec database and lockfile; it exited 0.

## Rust vulnerabilities removed

The initial audit found four advisories in transitive crates. No Church Cap Rust API changed; only compatible lockfile selections were updated.

| Advisory | Previous dependency | Patched dependency | Dependency path |
|---|---|---|---|
| `RUSTSEC-2026-0194` | `quick-xml` 0.38.4 | `quick-xml` 0.41.0 | Tauri → plist |
| `RUSTSEC-2026-0195` | `quick-xml` 0.38.4 | `quick-xml` 0.41.0 | Tauri → plist |
| `RUSTSEC-2026-0285` | `rustls` 0.23.43 | `rustls` 0.23.46 (current lockfile) | Tauri updater → reqwest/rustls |
| `RUSTSEC-2026-0009` | `time` 0.3.45 | `time` 0.3.47 | Tauri/cookie/plist |

`plist` moved from 1.8.0 to 1.10.0 to permit the fixed `quick-xml`. Rust tests, formatting, warning-as-error Clippy, and cargo-audit all passed after the lockfile change.

### rustls advisories of 14 October 2026

The Windows v0.9.0 build gate then failed on four new `rustls` 0.23.45 advisories. `rustls` 0.23.46 fixes all four and remains locked after the Tauri refresh.

### zip advisories of 17 October 2026

The Windows v0.9.0 build gate failed on three new advisories in `zip` 4.6.1: `RUSTSEC-2026-0367` (SUID/SGID bits kept on extraction), `RUSTSEC-2026-0368` (extracted symlinks may point outside the destination) and `RUSTSEC-2026-0369` (permissions applied through extracted symlinks). Only `zip` 9.0.0 and later is patched, and `tauri-plugin-updater` 2.14.0 requires `zip` 4.

`zip` came only from the updater's default `zip` feature. On Windows, that feature lets the updater unpack a Tauri v1-style `.exe.zip` or `.msi.zip` bundle after the signature check. Church Cap does not use that format: `createUpdaterArtifacts` is `true`, so the Windows update package is the signed NSIS `.exe` itself. The macOS `.app.tar.gz` path uses `tar` and `flate2`, which the updater always includes on macOS. Linux uses the CLI update path and does not build the desktop wrapper.

`Cargo.toml` now enables only the updater's `rustls-tls` and `system-proxy` features, the defaults minus `zip`. The lockfile drops `zip` 4.6.1, `arbitrary` 1.4.2 and `derive_arbitrary` 1.4.2 and changes nothing else. The TLS backend, proxy handling, signature verification and macOS archive handling are unchanged. A Windows update package in the old zip format would now be rejected as an invalid updater format rather than unpacked.

### emSign distrust advisories of 19–20 October 2026

The Windows v0.9.0 build gate then failed on `RUSTSEC-2026-0382` in `rustls-webpki` 0.103.14 and `RUSTSEC-2026-0383` in `webpki-root-certs` 1.0.9 (both CVE-2026-111943). Affected versions can accept certificate paths through distrusted emSign intermediates whose private keys are now public. `rustls-webpki` 0.103.16 rejects those intermediate keys, and `webpki-root-certs` 1.0.10 removes the `emSign ECC Root CA - G3` root.

`rustls-webpki` verifies certificates for the updater's HTTPS client only (Tauri updater → reqwest → rustls). An attacker with one of the leaked keys could intercept updater HTTPS, but cannot forge an update: the updater still checks the minisign signature against trust root `25BF3CCF4B6CBB01` before installing. `webpki-root-certs` is in the lockfile only through `rustls-platform-verifier` on other targets; `cargo tree` shows it in no Windows, macOS or Linux build.

The lockfile now selects `rustls-webpki` 0.103.16 and `webpki-root-certs` 1.0.10. Both are patch releases with unchanged dependency lists, and no other lockfile entry or Church Cap source changed.

### Tauri 2.12 refresh

`Cargo.lock` now selects `tauri` 2.12.4, `tauri-build` 2.7.3, `tauri-plugin-updater` 2.14.0, `tauri-plugin-single-instance` 2.5.4, and `tauri-plugin-opener` 2.7.2. `package-lock.json` selects `@tauri-apps/cli` 2.12.3. Tauri 2.12 raises the minimum Rust version to 1.90, reflected in `Cargo.toml`.

The [Tauri 2.12 release notes](https://github.com/tauri-apps/tauri/releases/tag/tauri-v2.12.4) and [updater changelog](https://github.com/tauri-apps/plugins-workspace/blob/v2/plugins/updater/CHANGELOG.md) add configuration options but require no change to this app's `tauri.conf.json` or `tauri.macos.conf.json`: Church Cap does not use webview downgrade options, app-bound domains, transparent window effects, or webview updater commands. The updater now re-verifies package bytes before installation (2.14.0), rejects non-canonical Ed25519 signatures (2.13.3), and has safer macOS replacement/restore behaviour (2.13.2). Church Cap still calls the Rust-owned updater API and requires an operator click to install. The configured minisign public key remains identical to `packaging/updater/church-cap-updater-public.key`, with trust root `25BF3CCF4B6CBB01`; no private updater material was accessed.

The [single-instance changelog](https://github.com/tauri-apps/plugins-workspace/blob/v2/plugins/single-instance/CHANGELOG.md) records Windows focus and timeout changes. The desktop control-window callback is unchanged; Winnie should validate second-instance focus on Windows. Generated capability schemas gained Tauri's new permission identifiers, while `capabilities/default.json` remains `core:default` for the control window and grants no new explicit updater command.

| Advisory | Summary | Church Cap exposure |

| `RUSTSEC-2026-0347` | Buffered data can go to the outer server after an ECH rejection | Not reachable. Church Cap does not enable ECH. |

`rustls` is used only by the Tauri updater's HTTPS client (Tauri updater → reqwest → hyper-rustls/tokio-rustls), with the `ring`, `std` and `tls12` features on Windows and macOS. The engine, the web application and the Linux CLI do not use it. The exposure is low, but the patched release removes the findings rather than accepting them.

| Transformers | 4.57.6 | `PYSEC-2026-2289` | Affects `AutoModelForCausalLM` and attacker-selected model configuration. Church Cap uses pinned SMaLL-100 `M2M100ForConditionalGeneration`, not a causal-language model. |

The CI exceptions remain tied to these exact IDs so any newly reported Python advisory fails the job. They are reachability exceptions, not a claim that the upstream packages are fixed.

## Why the affected Python packages are not blindly upgraded

- Current CTranslate2 conversion and the reviewed SMaLL-100/Tigrinya paths target Transformers 4.x. The relevant upstream fixes require Transformers 5.x and need a dedicated translation compatibility migration.
- Argos Translate 1.11.0 is the current Church Cap integration and pins Stanza 1.10.1 exactly. Overriding the dependency without an upstream-compatible Argos release would create an unsupported resolver state.
- Church Cap therefore fails closed around model identity, uses immutable model revisions, prefers SafeTensors, passes `trust_remote_code=False`, validates custom tokenizer content/paths, validates Argos archives, and removes Stanza from the runtime call path.

`PYSEC-2026-3929` and `PYSEC-2026-4174` are weaker than the "not invoked" rows: they hold only while every Hugging Face load in `app/` and `scripts/install-*` uses a full 40-character commit pin or a local directory with `local_files_only=True`, and while `trust_remote_code=True` and `custom_generate` are never used. `tests/test_security_controls.py` checks these conditions at the call sites. It cannot see inside libraries: CTranslate2 4.8.x `TransformersConverter` loads the model with the given `revision` but loads its config and tokenizer from the repository's default branch. Those two loads reach neither advisory (no `save_pretrained()`, no custom-generate fetch), and pinning them is tracked separately. Changing either pinned commit is release-blocking until the new commit is shown to contain no chat template and no `custom_generate/` directory. Any new `save_pretrained()` call, and any load of a user-selected or unpinned repository, is release-blocking. The Transformers 5.10+ refresh removes both exceptions.

Any future feature that loads arbitrary Hugging Face repositories, X-CLIP, Trainer checkpoints, a causal LM, LightGlue, a Stanza model, or user-supplied model/checkpoint files invalidates this decision and is release-blocking until re-audited.

## Release follow-up

- Run all four audits against the final accepted commit and exact lockfiles.
- Keep the Rust audit in CI so a newly disclosed locked-crate vulnerability fails future changes.
- Reassess the five remaining RustSec maintenance/unsoundness warnings when updating Tauri.
- Plan a separately tested Transformers 5.x and Argos/Stanza dependency refresh rather than changing the live translation stack during release packaging.
- Rebuild and re-sign every platform artifact after any dependency or lockfile change.
